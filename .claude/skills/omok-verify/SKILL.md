## 1. 원칙

**"완료를 주장하기 전에 근거를 확인한다."** 코드를 읽어서 내리는 판정은 이 스킬의 산출물이 아니다 — 전부 실행 증거로 뒷받침한다.

세 가지가 이 프로젝트에서 특히 잘 틀린다:
- **AI 강도는 코드로 판정 불가.** "어려움이 정말 어려운지"는 selfplay를 돌려야만 안다.
- **selfplay는 색을 교대하지 않으면 무의미하다.** 자유룰 오목은 흑 선공 필승이 증명돼 있어(Allis 1994), 한 색으로만 돌린 승률은 실력인지 선공 프리미엄인지 구분되지 않는다.
- **단위 테스트 통과 ≠ 아이가 쓸 수 있음.** 터치 타깃이 6.5mm라 실측 없이는 알 수 없다.

**게이트 규칙**: L1이 실패하면 **거기서 멈춘다.** 하위 레벨이 깨진 상태의 상위 레벨 결과는 정보가 아니라 노이즈다.

## 2. L0 — 사전 확인 (자유도: low)

`tests/` 디렉터리에 실행할 테스트 파일이 있는지 확인한다.

**없으면 여기서 중단한다.** 부재를 명시적으로 보고하고, `test-results.json`을 **쓰지 않는다.**
없는 결과를 "통과"로 간주하거나 빈 결과 파일을 만드는 것은 이 스킬의 존재 이유를 정면으로 배반한다.

## 3. L1 — 단위 테스트 (자유도: low)

출력을 파일로 남겨야 증거로 적립된다(`*-result.txt`가 증거 패턴).

Run these exactly — **플래그 추가 금지**:

```
node tests/board.test.js    2>&1 | Out-File -Encoding utf8 _workspace/runs/L1-board-result.txt
node tests/patterns.test.js 2>&1 | Out-File -Encoding utf8 _workspace/runs/L1-patterns-result.txt
node tests/ai.test.js       2>&1 | Out-File -Encoding utf8 _workspace/runs/L1-ai-result.txt
node tests/render.test.js   2>&1 | Out-File -Encoding utf8 _workspace/runs/L1-render-result.txt
node tests/wiring.test.js   2>&1 | Out-File -Encoding utf8 _workspace/runs/L1-wiring-result.txt
node tests/tactics.test.js  2>&1 | Out-File -Encoding utf8 _workspace/runs/L1-tactics-result.txt
node tests/puzzle.test.js   2>&1 | Out-File -Encoding utf8 _workspace/runs/L1-puzzle-result.txt
node tests/lessons.test.js  2>&1 | Out-File -Encoding utf8 _workspace/runs/L1-lessons-result.txt
node tests/coach.test.js    2>&1 | Out-File -Encoding utf8 _workspace/runs/L1-coach-result.txt
node tests/omok-doc-sync.test.js 2>&1 | Out-File -Encoding utf8 _workspace/runs/L1-omok-doc-sync-result.txt
node tests/flow.test.js     2>&1 | Out-File -Encoding utf8 _workspace/runs/L1-flow-result.txt
```

`flow.test.js`는 가짜 DOM(`tests/_dom-stub.js`) 위에서 **game.js·lesson-flow.js·ui.js를 통째로 구동**한다.
메뉴 → 교실 → 시범 → 퍼즐(오답·정답·마무리) → 써보기 → 혼자 하기에서 코치 개입·무르기·승리까지 실제 핸들러로 누른다.
Chrome 확장이 없을 때 L3의 11~15번 항목을 이것으로 대신할 수 있다. 다만 **보이는 것**(겹층이 실제로 그려지는가, 시트가 판을 가리지 않는가, 아이패드 배치)은 여전히 L3·L4의 몫이다.

⚠️ `Tee-Object`에 `Select-Object -First N`을 이어 붙이지 말 것 — 파이프가 끊겨 결과 파일이 잘린 채 저장된다(실측된 함정). 파일로 받은 뒤 따로 읽는다.

그 다음 결과 파일들을 **Read 도구로 읽는다** — Bash `cat`으로는 증거가 적립되지 않는다(의도된 설계: Read 유도).

**합격 기준**
- board: 4방향 5목 · **장목(6목 이상도 승리)** · **경계(0행/14행/0열/14열)** · 행 경계를 넘지 않음 · 무르기 정책 전부 통과
- patterns: **경계 접촉 3**(0행의 3을 열린3으로 오분류하는 버그) · 끊어진 패턴(`●●.●`) · 양쪽 막힌 4는 위협 아님 · 등급 순서 전부 통과
- ai: 하드 규칙 우선순위(**이길 수 있으면 막지 않고 이긴다**) · 쉬움의 결정론적 핸디캡 · 쌍삼 인식
- render: **DPR 1·2·3·4에서 터치 판정 동일**(그리기 좌표계와 터치 좌표계가 섞이면 여기서 걸린다) · 225 교차점 왕복
- wiring: HTML의 모든 `data-action`에 핸들러가 있고, `ui.js`가 찾는 id가 전부 존재하는가.
  **버튼이 아무 반응도 안 하는 종류의 결함은 브라우저 없이 문자열 대조만으로 잡힌다** — L3을 못 할 때 특히 중요하다.
  game.js에서 import로 닿는 모듈이 전부 오목 워커 캐시 목록에 있는가(정적 import 하나가 빠지면 오프라인에서 게임 전체가 안 뜬다).
- tactics: 띈삼도 삼 · 가장자리에 붙은 삼은 삼이 아님 · 쌍삼/사삼/사사 구분 · **막는 자리 열거**(붙은 삼은 바로 옆 둘, 띈삼은 가운데+양끝 셋) · 연속 사 깊이
- puzzle: 레슨마다 시드 고정 40판이 **전부 풀리고 정답 열거가 완전**(정답 아닌 빈칸에 기술이 성립하지 않음) · 마무리 퍼즐은 정답만 두면 반드시 이김 · 방해돌이 실제로 들어감
- lessons: 모든 시범의 `expect`가 그 자리에서 엔진으로 성립 · 견본이 대칭 8가지 × 위치 2에서 전부 건전(레슨 9는 깊이 2로 못 이겨야 함)
- coach: 다섯 놓침·상대 사 안 막음·사삼 놓침·연속 사 놓침·삼 안 막음에 끼어들고, 이기는 수·못 막는 상황·되받아치는 사에는 조용
- omok-doc-sync: 지침서의 레슨 표·별 규칙·힌트 횟수·코치 규칙 표·배지 표·상수 이름이 코드와 일치
- flow: 배우기 → 카드 → 시범 다음/이전 → 퍼즐 오답 말풍선(bad)·정답 말풍선(good)·마무리 퍼즐이 다섯으로 끝남 → 별 둘 → 써보기가 게임 화면 → 혼자 하기에서 **코치가 AI보다 먼저** 끼어들고 무르기가 내 돌 하나만 거두며 다섯을 두면 결과 카드

**FAIL이 1건이라도 있으면 출력 원문을 그대로 인용해 보고하고 여기서 중단한다.** L2로 넘어가지 않는다.

## 4. L2 — AI selfplay (자유도: low)

```
node tests/ai-selfplay.js --games 8 --time 300 2>&1 | Out-File -Encoding utf8 _workspace/runs/L2-selfplay-result.txt
```

64판을 두므로 **10분 이상 걸린다.** 백그라운드로 돌리고 다른 일을 하다 결과를 받는다.
결과 파일을 Read 도구로 읽는다.

**합격 기준 — 순서대로 확인한다**

1. **색 교대 증거가 출력에 있는가.** 색별 전적이 분리 기록돼 있어야 한다.
   없으면 **결과를 신뢰하지 않고 중단한다** — 색 편향된 데이터로 서열을 판정하는 것은 무효한 검증이다.
2. **대조군(보통 vs 보통)이 있는가.** 자유룰은 흑 선공이 구조적으로 유리하다. 대조군 없이
   "백이 졌다"를 보면 실력 탓인지 선공 탓인지 영원히 구분할 수 없다.
3. **서열**: 어려움 > 보통 > 쉬움 (무승부는 제외하고 승부 난 판으로 본다)
4. **무승부가 과반이면 측정이 퇴화한 것이다.** 실력이 비슷한 두 엔진은 같은 개시 국면에서
   매번 같은 교착에 빠져 225수 무승부만 쌓인다. 개시 국면 무작위화가 살아 있는지 확인한다.
5. **쉬움의 핸디캡이 의도대로인가**: 쉬움은 상대의 4목은 막고 열린3은 안 막는다.
   4목을 막지 못하고 지는 판이 다수면 핸디캡이 아니라 버그다.

**서열이 뒤집혔으면 NEEDS_WORK다.** "쉬움도 나름 강하네요"류의 합리화나 난이도 라벨만 바꾸는 회피는 금지다.

## 5. L3 — 브라우저 실측 (자유도: medium)

정적 서버를 띄우고(`npm run serve` → http://localhost:4173/) Chrome을 **390×844**(폰 세로) 뷰포트로 맞춰 조작한다.
⚠️ `file://`로 열면 ES 모듈도 Web Worker도 CORS로 죽는다 — 반드시 서버로 띄운다.
⚠️ Chrome 확장이 연결돼 있지 않으면 이 단계는 **수행 불가**다. 조용히 건너뛰지 말고
`test-results.json`에 `SKIPPED` + 사유를 남기고 사용자에게 알린다.

체크리스트. 각 항목의 스크린샷을 `_workspace/screenshots/`에 남기고 Read로 읽는다:

| # | 항목 | 무엇을 본다 |
|---|---|---|
| 1 | 1인 대전 · 쉬움 | AI가 4목은 막고 열린3은 안 막는가 (아이가 이길 수 있는가) |
| 2 | 1인 대전 · 보통 | 실수 없이 막는가 |
| 3 | 1인 대전 · 어려움 | 사고 중 **UI가 얼어붙지 않는가**(Worker 동작 증거), 1.5초 안에 응답 |
| 4 | 2인 대전 | 차례 전환, 상단 표시 |
| 5 | 두 번 탭 확정 | 미리보기 → 같은 자리 재탭 확정. 잘못 짚고 다른 칸 재선택 가능 |
| 6 | 무르기 | AI 선착(아이가 백) 상황 포함 — **차례가 꼬이지 않는가** |
| 7 | 설정 영속 | 변경 → 새로고침 → 유지되는가 |
| 8 | 가장자리 착수 | 0행/14열에 정확히 놓이는가 (좌표 변환 반 칸 밀림 검출) |
| 9 | **가로 모드** | 판과 버튼이 화면 밖으로 나가지 않는가 |
| 10 | 효과음 | 첫 터치 후 소리가 나는가 (`audioCtx.resume()` 누락은 **에러 없이 조용히 무음**이라 실측으로만 잡힌다) |
| 11 | 오목 교실 · 보기 | 배우기 → 레슨 카드 → 시범이 "다음"으로 넘어가고 돌 번호·줄 강조·물음표가 보이는가. "이전"으로 되돌아가는가 |
| 12 | 오목 교실 · 찾기 | 퍼즐에서 오답 시 빨간 X와 설명 말풍선, 정답 시 초록 말풍선과 줄 강조. 마무리 퍼즐(쌍삼 등)은 상대 응수 뒤 계속 둘 수 있고 다섯에서 끝나는가. 5문제 뒤 결과와 별 |
| 13 | 오목 교실 · 써보기 | "써보기 시작!"이 게임 화면으로 가고, 결과 카드에 "교실로" 버튼이 있으며, 이기면 별이 켜지는가 |
| 14 | 코치 | 혼자 하기(코치 켬)에서 상대 사를 안 막으면 **AI가 두기 전에** 아래쪽 시트가 뜨고 초록 자리가 표시되는가. 무르기 → 돌이 거둬지고 내 차례, 그냥 둘래요 → AI가 두는가 |
| 15 | 배지 | 실전에서 쌍삼을 두면 "쌍삼!" 토스트가 뜨고 교실 화면의 배지에 횟수가 오르는가 |

콘솔 에러도 함께 수집해 `_workspace/runs/L3-console.txt`로 남긴다.

## 6. L4 — 실기기 (자유도: high, 조건부)

**언제 필요한가** — 매 변경마다 요구하면 절차가 무거워져 우회하게 된다:
- **필요**: UI·조작·레이아웃을 바꿨을 때 / **APK 빌드 직전(필수 1회)**
- **불필요**: AI 로직이나 테스트만 바꿨을 때

`cf-tunnel` 스킬로 임시 주소를 발급해 딸아이 폰에서 직접 플레이시킨다.
관찰 대상은 기능이 아니라 **아이의 손**이다: 짚기 어려워하는가, 어느 버튼을 못 찾는가, 어느 난이도에서 흥미를 잃는가.
관찰 결과를 `_workspace/runs/L4-field-notes.md`에 기록한다. 끝나면 터널을 닫는다.

## 7. 결과 기록 (자유도: low)

`test-results.json`에 기록한다. **증거 파일을 Read하지 않은 상태에서는 훅이 이 쓰기를 차단한다**(의도된 게이트).

```json
{
  "timestamp": "2026-08-13T10:30:00+09:00",
  "levels": {
    "L1": {"status": "PASS|FAIL|SKIPPED", "evidence": "_workspace/runs/L1-board-result.txt", "note": ""},
    "L2": {"status": "...", "evidence": "...", "note": "어려움 흑 9/10, 백 8/10 vs 보통"},
    "L3": {"status": "...", "evidence": "_workspace/screenshots/", "note": ""},
    "L4": {"status": "PASS|SKIPPED", "evidence": "...", "note": "SKIPPED 시 생략 사유 필수"}
  },
  "verdict": "PASS|NEEDS_WORK",
  "blocking": ["미해결 항목을 자기완결적으로 — 다음 세션이 이것만 읽고 착수할 수 있게"]
}
```

`SKIPPED`에는 **반드시 사유를 쓴다.** 사유 없는 SKIPPED는 은폐다.

## 8. 판정 위임

L1~L3을 마쳤으면 `omok-referee` 에이전트에게 블랙박스 판정을 요청한다.
전달할 것은 정확히 셋이다 — **산출물 경로 + 성공 기준 + 원 사용자 목표 원문**.
**구현 히스토리와 내가 겪은 시행착오는 전달하지 않는다** — 생산자의 합리화를 물려받은 검증은 검증이 아니라 공감이다.

referee의 첫 줄이 `NEEDS_WORK`면 그 발견사항이 다음 작업의 착수 지점이다. 스스로 판정을 뒤집지 않는다.

## 9. 부분 재실행

"L2만 다시" 같은 요청에는 **해당 레벨만 실행한다.** 다른 레벨의 이전 결과는 `test-results.json`에서 유지하고, 재실행한 레벨의 항목만 갱신한다.
전면 재실행은 사용자가 명시적으로 요구했을 때만 한다 — 부분 요청을 전면 실행으로 확대하면 사용자가 스킬을 우회하게 된다.
