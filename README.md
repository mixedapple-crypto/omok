# 우리집 게임숲

초등 3학년 딸을 위한 **광고·과금·네트워크 요청이 전혀 없는** 게임 모음.
사이트 루트는 게임 선택 포털이고, 게임은 각각 하위 폴더에 산다.

- **오목** (`www/omok/`) — 1인 대전(AI 쉬움/보통/어려움) + 2인 대전(한 폰 번갈아).
  자유룰 — 금수 없음, **5목 이상이면 승리**(장목도 승리).
  **오목 교실**(메뉴의 "배우기")이 레슨 열 개로 다섯·사·삼·쌍삼·사삼·사사·연속 사·미리 막기를
  보기 → 찾기(퍼즐) → 써보기(실전) 순으로 가르친다. 혼자 하기에는 놓친 필승수·수비를 즉시 지적하는
  **코치**가 있고, 실전에서 쌍삼·사삼·사사를 성공하면 **배지**가 쌓인다. 규칙의 사람용 정본은
  [오목 교실 지침서](documents/오목-교실-지침서.md)다.
- **숫자숲 친구들** (`www/math/`) — 덧셈·뺄셈 연습 몬스터 배틀. 단일 HTML, 별도 빌드 없음.
  보상 체계의 실제 수치는 [숫자숲 친구들 지침서](documents/숫자숲-친구들-지침서.md)에 정리해 두었다.
- **곱셈 바다** (`www/mul/`) — 곱셈과 나눗셈을 **세로셈으로** 연습한다. 20스테이지 4구역이고
  곱셈(올림 없음) → 나눗셈 → 곱셈(올림) → 나눗셈 순이다. 진행·점수·용돈 체계는 숫자숲과 같다.
  1구역은 세로셈 두 판 → 십의 자리부터 분해해서 더하기 두 판 → 암산 보스, 3구역(올림)은
  분해 두 판 → 올림을 보여주고 답 한 번에 두 판 → 암산 보스 순으로 올라간다.
  나눗셈은 네 구역 모두 나머지 0이고, 2구역은 세 자리 ÷ 한 자리, 4구역은 세 자리 ÷ 두 자리다.
  2구역은 곱한 값만 두 판 → 몫과 뺀 값 두 판 → 몫만 보스, 4구역은 몫만 넣고 바로 보여주는 두 판 →
  몫과 뺀 값 두 판 → 몫만 보스다 — 곱셈과 같이 보스는 도움만 걷어낸다.
  구역을 늘리려면 `ZONES` · `ANIMALS` · `MIX` 세 배열을 이어 붙이면 스테이지 수가 알아서 늘어난다.
  문제 형식과 보상의 사람용 정본은 [곱셈 바다 지침서](documents/곱셈-바다-지침서.md)다.
- **부모님 안내** (`www/guide/`) — 포털 맨 아래 "📖 부모님 안내". 네 지침서에서 부모용 절만 뽑아
  `npm run guide`가 만든다. 손으로 고치지 않으며, `tests/guide.test.js`가 지침서와 어긋나면 죽는다.
- **구구단 로켓** (`www/gugudan/`) — 구구단을 "생각 없이 나오는" 수준으로 올리는 속도 훈련. 하루 7분:
  연료 채우기(엔진이 고른 24문제) → 로켓 레이스(최근 5회 중간값 유령과 경주) → 구두 카드 → 거꾸로 암송.
  사실 72개마다 답 시간과 정확도를 재서 약한 것을 더 자주 내되 잘 아는 것도 굶기지 않고, 혼동쌍은 아이의
  오답에서 만든다. 최종 목표는 **거꾸로 36초**이고 숙달 인증은 부모와 하는 무작위 구두 72개다.
  규칙의 사람용 정본은 [구구단 로켓 지침서](documents/구구단-로켓-지침서.md)다.
- **의존성 0** — 프레임워크도 빌드 도구도 없다. 광고 SDK가 끼어들 여지도 없다.
- `www/`에 있는 것이 그대로 APK가 된다 (Capacitor의 기본 webDir)

## 실행

```bash
npm run serve       # http://localhost:4173/
```

⚠️ **`index.html`을 더블클릭해서 열면 안 된다.** `file://`에서는 ES 모듈도 Web Worker도
CORS로 전부 죽어 백지 화면이 된다. 반드시 서버로 띄운다.

딸아이 폰에서 확인하려면 `cf-tunnel` 스킬로 임시 주소를 발급받는다.

## 검증

```bash
npm test            # 단위 테스트 (오목 · 오목 교실 · 구구단 로켓 엔진/시뮬레이션/배선/흐름 · 문서 동기화 · math · mul)
npm run selfplay    # AI끼리 대국시켜 난이도 서열 확인 — 10분 이상 걸린다
```

전체 검증 절차는 `omok-verify` 스킬이 강제한다(L1 단위 → L2 selfplay → L3 브라우저 실측 → L4 실기기).
판정은 `omok-referee` 에이전트가 별도로 내린다 — 만든 사람이 자기 것을 채점하지 않게 하기 위해서다.

### 서비스 워커가 둘인 이유

포털(`www/sw.js`, 스코프 `/`)과 오목(`www/omok/sw.js`, 스코프 `/omok/`)이 각자 자기 몫만 캐시한다.
오목을 포털 워커가 같이 캐시하면 같은 파일이 두 캐시에 들어가 배포 후 한쪽만 갱신돼 버전이 엇갈린다.

⚠️ **캐시 저장소는 출처 단위로 공유된다.** 그래서 두 워커 모두 `activate`에서
자기 접두사(`portal-`, `omok-`)로 걸러 지운다. "내 것이 아닌 건 지운다"로 짜면
배포마다 서로의 캐시를 지워 오프라인이 조용히 깨진다. 실제로 오목 워커가 그 상태였다.

포털 워커는 캐시를 찾을 때 `caches.match()`가 아니라 자기 캐시의 `cache.match()`를 쓴다.
전자는 출처의 모든 캐시를 뒤지므로, 포털 전환 이전에 루트에 깔린 옛 오목 캐시가 걸려
포털 자리에 옛 오목 화면이 나온다.

## AI 설계에서 중요한 것 세 가지

전부 실측으로 정해졌다. 근거는 `_workspace/decisions.md`와 `_workspace/runs/`에 있다.

1. **승리수와 필수 방어수는 점수가 아니라 순서로 처리한다.**
   가중치로 다루면 내 승리수와 상대 차단수가 동점이 되어 **AI가 이긴 판을 안 두고 막는다.**

2. **패턴은 문자열표가 아니라 기능적 정의로 분류한다.**
   `열린3 = 한 수로 열린4가 되는 모양`처럼 정의하면, 반상 가장자리에서 열림/막힘이
   뒤바뀌는 고질적 오분류가 자동으로 사라진다. 9칸 창의 6,561가지를 기동 시 표로 계산한다.

3. **어려움의 강함은 깊이가 아니라 VCF에서 나온다.**
   일반 탐색은 폭이 넓어 깊이 4가 한계지만, 4를 만드는 수만 두는 VCF는 분기가 2~4라
   8수 앞의 강제 승리를 본다. 초안처럼 탐색에게 위치 판단까지 맡겼더니 오히려 **보통보다 약했다** —
   그래서 위치 판단은 탐욕 점수가 하고 탐색은 강제 승/패만 가린다.

## 난이도

난이도의 실체는 **"상대의 열린3을 막느냐"** 하나다. 실측으로 이 축이 승률을 지배함을 확인했다.

| | 하는 일 | 아이가 배우는 것 | 초보 상대 승률 |
|---|---|---|---|
| **쉬움** | 상대의 4목(다음 수 5목)만 막고 **열린3은 절대 막지 않는다** | "3을 먼저 만들면 이긴다" | 초보가 **50%** 승 |
| **보통** | 열린3을 대체로 막지만 **가끔 놓친다**(60%). 상대의 쌍삼은 미리 못 읽는다 | "쌍삼을 만들면 통한다" | 초보가 **25%** 승 |
| **어려움** | 전부 막고, 쌍삼도 미리 읽고, VCF로 8수 앞 강제 승리까지 찾는다 | — | 초보가 **0%** 승 |

보통만 확률적이다. 결정론적 다이얼을 **여섯 가지 시도해 전부 무효**였고(수비 가중치 0.5~1.1,
시야 반경, 끊어진 위협 눈가림, 수비 단계 분리, VCF 유무), 승률은 늘 50% 아니면 0%로만 나왔다.
절벽이 오직 저 한 축에 있어 그 사이에 결정론적 중간이 없다. 근거는 `_workspace/decisions.md` D18~D19.

**주의**: 수비를 하드 규칙에서 낮추더라도 **점수 가중치를 함께 낮추지 않으면 아무 효과가 없다.**
점수가 도로 막아버린다. 튜닝 중 이 함정에 두 번 걸렸다.

## 아직 안 된 것

- **APK 빌드** — JDK 17 + Android 커맨드라인 도구 설치가 필요하다(~3-4GB).
  설치 후 `npx cap init` → `npx cap add android` → `gradlew assembleDebug`.
  세로 고정과 안드로이드 뒤로가기 처리도 이 단계의 몫이다
  (`screen.orientation.lock()`은 브라우저 탭에서 거부되므로 웹에서는 불가능하다).
- **L3 브라우저 실측 · L4 실기기** — `_workspace/runs/`의 기록 참조.
