# 오목

초등 3학년 딸을 위한 **광고·과금·네트워크 요청이 전혀 없는** 오목 게임.
1인 대전(AI 쉬움/보통/어려움) + 2인 대전(한 폰 번갈아).

- **규칙**: 자유룰 — 금수 없음, **5목 이상이면 승리**(장목도 승리)
- **의존성 0** — 프레임워크도 빌드 도구도 없다. 광고 SDK가 끼어들 여지도 없다.
- `www/`에 있는 것이 그대로 APK가 된다 (Capacitor의 기본 webDir)

## 실행

```bash
npm run serve       # http://localhost:4173/
```

⚠️ **`index.html`을 더블클릭해서 열면 안 된다.** `file://`에서는 ES 모듈도 Web Worker도
CORS로 전부 죽어 백지 화면이 된다. 반드시 서버로 띄운다.

딸아이 폰에서 확인하려면 `cf-tunnel` 스킬로 임시 주소를 발급받는다.

## 검증

```bash
npm test            # 단위 테스트 (board · patterns · ai · render)
npm run selfplay    # AI끼리 대국시켜 난이도 서열 확인 — 10분 이상 걸린다
```

전체 검증 절차는 `omok-verify` 스킬이 강제한다(L1 단위 → L2 selfplay → L3 브라우저 실측 → L4 실기기).
판정은 `omok-referee` 에이전트가 별도로 내린다 — 만든 사람이 자기 것을 채점하지 않게 하기 위해서다.

## 구조

```
www/                  ← 이대로 APK에 들어간다
├─ index.html         화면 3개(메뉴·게임·결과)를 class 토글로 전환
├─ css/style.css
└─ js/
   ├─ board.js        반상·착수·승패 판정 (순수 로직, DOM·패턴에 의존하지 않는다)
   ├─ patterns.js     돌 패턴 등급 판정 — AI 전용
   ├─ ai.js           난이도별 엔진
   ├─ ai-worker.js    AI를 별도 스레드에서 (사고 중 화면이 얼지 않게)
   ├─ render.js       캔버스 그리기 + 터치 좌표 변환
   ├─ audio.js        효과음 합성 (음원 파일 0)
   ├─ storage.js      설정·전적
   ├─ ui.js           DOM 조작만 (게임 규칙을 모른다)
   └─ game.js         게임 흐름 총괄
tests/                프레임워크 없는 단위 테스트
_workspace/           결정 원장, eval 스펙, 실행 기록
```

## AI 설계에서 중요한 것 세 가지

전부 실측으로 정해졌다. 근거는 `_workspace/decisions.md`와 `_workspace/runs/`에 있다.

1. **승리수와 필수 방어수는 점수가 아니라 순서로 처리한다.**
   가중치로 다루면 내 승리수와 상대 차단수가 동점이 되어 **AI가 이긴 판을 안 두고 막는다.**

2. **패턴은 문자열표가 아니라 기능적 정의로 분류한다.**
   `열린3 = 한 수로 열린4가 되는 모양`처럼 정의하면, 반상 가장자리에서 열림/막힘이
   뒤바뀌는 고질적 오분류가 자동으로 사라진다. 9칸 창의 6,561가지를 기동 시 표로 계산한다.

3. **어려움의 강함은 깊이가 아니라 VCF에서 나온다.**
   일반 탐색은 폭이 넓어 깊이 4가 한계지만, 4를 만드는 수만 두는 VCF는 분기가 2~4라
   8수 앞의 강제 승리를 본다. 초안처럼 탐색에게 위치 판단까지 맡겼더니 오히려 **보통보다 약했다** —
   그래서 위치 판단은 탐욕 점수가 하고 탐색은 강제 승/패만 가린다.

## 난이도

난이도의 실체는 **"상대의 열린3을 막느냐"** 하나다. 실측으로 이 축이 승률을 지배함을 확인했다.

| | 하는 일 | 아이가 배우는 것 | 초보 상대 승률 |
|---|---|---|---|
| **쉬움** | 상대의 4목(다음 수 5목)만 막고 **열린3은 절대 막지 않는다** | "3을 먼저 만들면 이긴다" | 초보가 **50%** 승 |
| **보통** | 열린3을 대체로 막지만 **가끔 놓친다**(60%). 상대의 쌍삼은 미리 못 읽는다 | "쌍삼을 만들면 통한다" | 초보가 **25%** 승 |
| **어려움** | 전부 막고, 쌍삼도 미리 읽고, VCF로 8수 앞 강제 승리까지 찾는다 | — | 초보가 **0%** 승 |

보통만 확률적이다. 결정론적 다이얼을 **여섯 가지 시도해 전부 무효**였고(수비 가중치 0.5~1.1,
시야 반경, 끊어진 위협 눈가림, 수비 단계 분리, VCF 유무), 승률은 늘 50% 아니면 0%로만 나왔다.
절벽이 오직 저 한 축에 있어 그 사이에 결정론적 중간이 없다. 근거는 `_workspace/decisions.md` D18~D19.

**주의**: 수비를 하드 규칙에서 낮추더라도 **점수 가중치를 함께 낮추지 않으면 아무 효과가 없다.**
점수가 도로 막아버린다. 튜닝 중 이 함정에 두 번 걸렸다.

## 아직 안 된 것

- **APK 빌드** — JDK 17 + Android 커맨드라인 도구 설치가 필요하다(~3-4GB).
  설치 후 `npx cap init` → `npx cap add android` → `gradlew assembleDebug`.
  세로 고정과 안드로이드 뒤로가기 처리도 이 단계의 몫이다
  (`screen.orientation.lock()`은 브라우저 탭에서 거부되므로 웹에서는 불가능하다).
- **L3 브라우저 실측 · L4 실기기** — `_workspace/runs/`의 기록 참조.
